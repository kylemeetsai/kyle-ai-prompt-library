=== description ===
Anthropic just released <strong>Claude Ship</strong>. In Claude Code, one command, <strong>/ship</strong>, saves your change, sends it for review on GitHub, checks it, and keeps fixing what comes back. <strong>You still hit merge.</strong> Here are the steps, plus a prompt that gets your project ready for your first /ship.

=== steps ===
<strong>You need:</strong> Claude Code on your computer and a GitHub account
<strong>Open Claude Code in your terminal</strong>, inside your project's folder. /ship works there, not in a regular Claude chat
<strong>Paste the setup prompt below.</strong> Claude checks your GitHub sign-in, keeps your keys and passwords out, and writes your review rules
<strong>Type /ship yourself.</strong> Claude opens a pull request, reviews your change, and keeps fixing what comes back while the window stays open
<strong>You hit merge.</strong> When Claude says the checks pass, merge it on GitHub. Claude never merges for you
<strong>Don't see /ship?</strong> Type <strong>claude update</strong> in your terminal, then restart Claude Code (sometimes twice)

=== notes ===
Good to know: the agents that review, fix and approve every pull request on their own are switched on by a company's Claude admin. On your own, /ship gives you the review and the fixes.
AI review can still miss bugs (Anthropic says so), so you're the last check before you merge.

=== prompt ===
Help me get set up to use /ship, the Claude Code command that opens a pull request on GitHub, reviews my change, and works on the feedback and failing checks. Go one step at a time, ask me one question at a time, and wait for my answer. Use plain English. Ask before you commit, push, change a file or create anything on GitHub. Never ask me for passwords or tokens, and never merge, approve or force-push anything.

1. Check the basics: is this folder a git project, is git 2.38 or newer, and is the GitHub CLI (gh) 2.63 or newer installed and signed in? If something is missing, give me the exact command and let me run it myself in my own terminal, including the sign-in (gh auth login, using the browser option). If I'm on Windows outside WSL, tell me /ship will review my change there but won't keep fixing it.
2. Check for secrets: make sure .env files, API keys and passwords are in .gitignore and not already committed, and look inside my changed files for keys too. Never show me a secret's value. If one is already committed, stop and walk me through fixing it first.
3. If this project isn't on GitHub yet, offer to create a private repo for it, and wait for my yes.
4. Interview me: What does this project do, in one sentence? What must never break (checkout, sign-up, a booking form)? Is there anything that should always get a person's eyes before it goes live? If I'm not sure, suggest an answer.
5. From my answers, write a short "Review rules" section in CLAUDE.md: what counts as important, what to ignore, and five nitpicks at most. Show it to me before you save it. Then, with my OK, commit and push the setup files (CLAUDE.md, .gitignore) to my main branch on their own, because /ship won't commit changes to those files for me.
6. Show me every uncommitted file, because /ship can commit all of them, and help me set aside anything that shouldn't go in.
7. In three plain sentences, tell me what /ship will do: commit, push, open a pull request, review it, then keep working on failing checks and comments while this window stays open. Remind me that I merge it myself, that typing /ship stop ends it, and that in Manual permission mode you'll ask me before each push or reply.
8. If I have no change ready, suggest one small, safe change and make it with me. Then tell me to type /ship myself.
